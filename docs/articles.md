# 글 저장·조회 확인

## 실행과 확인 순서

1. `backend`에서 `.\run-steam.ps1`로 API를 실행합니다. JDK 21과 로컬 실행용 JWT 키를 준비하고 Steam 수집 프로필을 활성화합니다.
2. `frontend`에서 `npm run dev`를 실행하고 [로컬 화면](http://127.0.0.1:5173)을 엽니다.
3. 첫 화면에서 로그인 없이 공개 뉴스 목록을 엽니다.
4. 서버 기동 약 10초 후 첫 Steam 수집을 시작합니다. 수집에 실패하면 관리자의 수집 이력을 확인합니다.
5. 제목을 선택하면 서버에서 상세 본문·게임·출처·발행 시각·썸네일을 읽어 표시합니다. 시간은 한국 시간이며 원문 링크로 Steam 공지를 열 수 있습니다.
6. 제목을 검색하고 게임을 필터링합니다. **Steam 전체 게임 검색**에서 게임을 고르면 서버가 공지를 즉시 수집합니다. Steam에서 정상 응답을 받은 게임은 드롭다운에 추가됩니다. 공개된 공지가 없으면 빈 목록을 표시합니다. 검색 조건과 페이지는 새로고침해도 유지됩니다.
7. API 서버를 종료했다가 같은 DB로 다시 실행하고 글 수와 ID가 유지되는지 확인합니다. 브라우저 새로고침은 현재 탭의 토큰으로 `/api/me`를 호출해 인증을 복원합니다. 토큰이 만료되었거나 서버의 JWT 키가 바뀌었다면 재로그인합니다.

데모 생성 기능은 제거했으며 기존 예시 글은 V5 마이그레이션에서 삭제합니다. 실제 수집·스케줄러 설정은 [2단계 수집 가이드](steam-ingestion.md)를 참고하세요.

## 저장 구조

`games`는 내부 ID와 Steam AppID, `sources`는 출처 코드·이름, `articles`는 출처/게임 FK·외부 ID·제목·본문·원문 주소·발행/저장 시각·공개 상태·데모 여부를 저장합니다. 게임 연결이 없으면 미분류입니다. 외부 ID는 숫자 변환 없이 문자열로 저장합니다.

`ArticleStore.store(Draft)`는 서버 내부 수집용 서비스입니다. 입력의 필수값·길이·참조 대상·HTTP(S) 원문 주소를 검사하고 신규 글을 `PUBLISHED`로 저장합니다. `(source_id, external_key)` 유일 제약으로 중복·동시 저장을 막고, 기존 글의 내용·게임 연결·`HIDDEN` 상태를 변경하지 않습니다. 일반 회원용 글 작성 API는 없습니다. 2단계에서 발췌·썸네일·버전을 추가했으며 V4가 기존 `external_id`의 이름을 `external_key`로 이관합니다.

## 조회 API

뉴스와 게임 조회 API는 인증 헤더 없이 호출할 수 있습니다. 토큰을 보내는 경우 유효하지 않은 토큰은 401, 정지 회원 토큰은 403입니다. 회원 인증이 실패하면 브라우저는 현재 뉴스 주소에서 비회원으로 다시 조회합니다.

| 메서드·경로 | 응답 |
| --- | --- |
| `GET /api/articles?page=0&size=20&steamAppId=105600&gameName=Terraria` | 필요 시 선택 게임을 수집한 뒤 `items`, `page`, `size`, `totalElements`, `totalPages` 반환 |
| `GET /api/articles/{id}` | `id`, `title`, `body`, `game`, `source`, `originalUrl`, `publishedAt`, `createdAt`, `demo` |
| `GET /api/games` | 내부 ID·게임명·Steam AppID 목록 |
| `GET /api/games/steam?q=Terraria&page=0` | Steam 게임명·AppID, 페이지 정보. Steam 상점 조회 실패 시 503 |

목록 항목은 상세의 본문 대신 `excerpt`를 포함합니다. 검색은 제목 부분 일치이며 대소문자를 구분하지 않고 `%`, `_`, `!`도 실제 문자로 검색합니다. `page`는 0부터, `size`는 1–50(기본 20), `q`는 최대 100자입니다. 프런트엔드는 페이지당 10건을 요청합니다. 발행 시각 내림차순, 같은 시각에서는 내부 ID 내림차순으로 정렬합니다. 잘못된 인자는 400 `INVALID_PARAMETER`, 빈 검색 결과는 200과 빈 `items`입니다.

`PUBLISHED`만 목록·상세에 노출합니다. 게임 필터는 내부 `gameId` 또는 `steamAppId`로 적용할 수 있습니다. 게임 연결이 없는 글은 전체 목록에서 ‘미분류’로 표시되고 게임 필터를 선택하면 제외됩니다. 숨김 글과 존재하지 않는 글의 상세는 모두 404 `ARTICLE_NOT_FOUND`이며 화면에서 목록으로 돌아가는 링크를 표시합니다. 본문은 일반 텍스트로 표시합니다.

게임을 지정한 조회는 직전 수집 결과에 따라 Steam 공지를 갱신합니다. Steam 연결 실패 시 저장된 공개 뉴스만 반환합니다. 동작 기준은 [온디맨드 수집 개선 가이드](https://app.notion.com/p/41dbcc84e50e81b19ea5d50490000c22)입니다.

## HTTP 검증

API·프런트엔드 서버를 모두 실행한 상태에서 프로젝트 루트에서 다음 명령을 실행합니다. 매번 테스트 회원 1명이 생성됩니다. 비밀번호와 토큰은 출력하거나 파일에 저장하지 않습니다.

```powershell
node scripts/http-smoke.mjs
```

가입·로그인·권한 검사, 목록과 최대 3건의 상세·게임 필터를 확인합니다. 수집된 글이 없으면 인증·빈 목록을 확인합니다.
